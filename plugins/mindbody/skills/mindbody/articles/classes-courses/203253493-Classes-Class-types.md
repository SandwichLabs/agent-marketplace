# Class types FAQ

Class types sit between service categories and individual classes/courses; clients can filter schedules by them and reports use them. Needed when adding, retiring or reorganizing class types, or setting up rentals.

## Where in Mindbody
- Direct link: https://clients.mindbodyonline.com/app/business/servicesandpricing/Classes
- Menu path: **Settings > Classic Setup > Class Types** (search "Class Types" in Settings)
- Menu path: **Services & Products > Classes** > **+Add a Class**

## Steps
### Add a class type while creating a class
1. **Services & Products > Classes**, click **+Add a Class**.
2. Enter name and category, click **Select** on the Class Type dropdown.
3. Pick an existing type or **Add New**, name it, click **Add**.
4. Finish the class details, click **Add**.

### Add from the Class Types screen
1. **Settings > Classic Setup > Class Types**, click **Add New Class Type** (top right).
2. Choose the service category it belongs under.
3. Enter **Name**.
4. Set **# Deducted** (sessions deducted per visit; normally 1, only change for point-based systems).
5. Optionally set **Sort Order** (default is alphabetical).
6. Click **Add New Class Type**.

### Deactivate or delete
1. Open the Class Types screen.
2. To deactivate: clear the **Active** checkbox, click **Save**.
3. To delete: click **Delete** at the far right of the row.

## Gotchas
- One class type cannot span multiple service categories; create a same-named type in the other category.
- Changing a class type does not update historical visit data. It sticks only if no clients are enrolled; if clients are enrolled the change is not reflected.
- Class types are not a filter in the Mindbody app (clients can only keyword-search); use categories/subcategories for app visibility.
- Rentals (rooms/equipment) need class types, especially if sold at Point of Sale; put them in their own service category (e.g. "Rentals") to set a default booking time. Rentals show on the Room Schedule calendar, not the class schedule. Even unscheduled rentals need a class type.
- No class types needed if the business has only appointments.
- Deletion is hard to undo; prefer deactivating (confirm with the user before deleting).
